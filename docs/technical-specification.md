# Техническое описание — «Командный центр входящих задач»

## 1. Назначение

Статическое веб-приложение для координатора, которое превращает 24 входящих
запроса в операционную картину для ежедневной планёрки: что горит сегодня, где
не хватает данных, кто перегружен, какие запросы — возможные дубли, и какую
сводку отправить руководителю.

Проектные правила и критерии готовности зафиксированы в `AGENTS.md`.
Ожидания пользователя — в `references/ux-spec.md` и `references/business-analysis.md`.

## 2. Стек

- HTML5 + CSS3 + JavaScript (ES5-совместимый, без сборки и генераторов);
- без внешних библиотек, фреймворков, CDN и API;
- данные хранятся в статическом массиве `app/data.js`;
- приложение открывается как статический сайт (`file://` или любой сервер);
- название и текст интерфейса — на русском языке.

## 3. Данные

Файл `app/data.js` содержит три глобальных объекта:

### `requests` — массив из ровно 24 запросов

Каждый запрос — объект:

| Поле | Тип | Пример | Пояснение |
|---|---|---|---|
| `id` | string | `"01"` | Исходный номер от `"01"` до `"24"` |
| `source` | string | `"почта"` | Один из 5 источников |
| `project` | string | `"Орион"` | Один из 11 проектов |
| `text` | string | «…обновить КП…» | Текст запроса |
| `deadline` | string \| null | `"сегодня до 17:00"` | Срок; `null` — требует уточнения |
| `assignee` | string \| null | `"Максим"` | Ответственный; `null` — требует уточнения |
| `priority` | string | `"high"` | `high` / `medium` / `low` |
| `dataStatus` | string | `"full"` | `full` / `missing_assignee` / `missing_deadline` |

Запросы с `assignee: null` (7 шт.: 02, 05, 09, 14, 17, 18, 22) и с `deadline: null`
(4 шт.: 04, 10, 20, 24) должны отображаться со словами «требует уточнения».

### `duplicateGroups` — 4 группы предположений

Каждая группа: `id`, `title`, `requestIds` (номера запросов), `description`,
`reason` («Почему похоже»).

1. Обновление КП «Орион» — 01, 07, 19;
2. Проверка лендинга перед запуском рекламы — 02, 08;
3. UTM-метки на лендинге — 12, 21;
4. Согласование даты вебинара — 05, 11, 17.

### `executors` — 11 исполнителей

Каждый: `name`, `count`, `hotCount`, `projects[]`.

## 4. Функциональные требования

### FR-1 Общий обзор (KPI)

Четыре карточки-индикатора: всего запросов, высокий приоритет, проблемы данных
(`dataStatus !== "full"`), количество групп дублей. Карточки кликабельны:
фильтр по высокому приоритету, фильтр по неполным данным, прокрутка к дублям
и сброс фильтров (по «Всего»).

### FR-2 «Фокус дня»

Запросы с `priority === "high"` и сроком, содержащим «сегодня» или «завтра».
Сортировка: сначала «сегодня», затем «завтра». Пустое состояние — сообщение
«Нет горящих задач на сегодня и завтра».

### FR-3 Таблица «Все запросы»

Карточки-строки: номер, текст, источник, проект, ответственный, срок, приоритет.
Строка хранит `data-id` для прокрутки из блока дублей.

### FR-4 Поиск и фильтры

- Поиск по тексту, ID, проекту, исполнителю, источнику (регистронезависимый);
- фильтры: источник (5), проект (11), приоритет (3), полнота данных (2);
- комбинирование по AND, мгновенное применение;
- кнопка «Сбросить фильтры» видна только при активных фильтрах;
- пустое состояние с подсказкой и кнопкой сброса.

### FR-5 «Нагрузка по команде»

Карточки исполнителей: имя, полоска загрузки (относительно максимума в команде),
число задач, горящие задачи, проекты. Цвет полоски: зелёный (≤1), жёлтый (2),
красный (≥3). Внизу — строка «Не назначено» с количеством запросов без
ответственного.

### FR-6 «Возможные дубли»

Вывод `duplicateGroups`: заголовок, кликабельные номера запросов (прокрутка
и подсветка строки таблицы), описание и причина «Почему похоже».

### FR-7 «Сводка для планёрки»

Автоматически сформированный текст: дата, общее число запросов, высокий
приоритет, количество требующих уточнения, «Фокус дня», топ-4 нагрузки,
число неназначенных, список дублей. Кнопка «Копировать сводку» использует
`navigator.clipboard.writeText()` с fallback на `document.execCommand("copy")`
и меняет подпись на «Скопировано ✓» на 2 секунды.

## 5. Нефункциональные требования

- NFR-1: статический сайт, запуск без сети и сервера;
- NFR-2: интерфейс читаем на экранах ≤ 768px (адаптивная сетка);
- NFR-3: кнопка копирования не ломает страницу при недоступном clipboard;
- NFR-4: `node --check app/app.js` и `node --check app/data.js` — без ошибок.

## 6. Критерии приёмки

| AC | Критерий |
|---|---|
| AC-01 | Существуют `app/index.html`, `app/styles.css`, `app/data.js`, `app/app.js` |
| AC-02 | В `data.js` ровно 24 запроса, номера от `"01"` до `"24"` |
| AC-03 | Каждый запрос содержит все поля из раздела «Данные» |
| AC-04 | Запросы с `null`-полями отображаются как «требует уточнения» |
| AC-05 | В разметке есть блок «Фокус дня» (`#focus-list`) |
| AC-06 | Есть блок «Нагрузка по команде» (`#workload-list`) и 11 исполнителей |
| AC-07 | Есть блок «Возможные дубли» (`#duplicates-list`) с `reason` у каждой группы |
| AC-08 | Есть KPI-контейнер (`#kpi-container`) и хендлеры 4 карточек |
| AC-09 | Есть поиск и фильтры: источник, проект, приоритет, полнота данных |
| AC-10 | Есть кнопка сброса фильтров и пустое состояние |
| AC-11 | Есть сводка для планёрки (`#summary-text`) и кнопка копирования |
| AC-12 | CSS содержит media-запрос для узкого экрана (≤768px) |
| AC-13 | `node --check` для `app/data.js` и `app/app.js` не даёт ошибок |

## 7. Структура приложения

```
app/
├── index.html   # интерфейс: KPI, фильтры, фокус дня, таблица, нагрузка, дубли, сводка
├── styles.css   # стили, сетка, индикаторы, адаптивность
├── data.js      # requests, duplicateGroups, executors, generateSummary()
└── app.js       # рендеринг, фильтры, поиск, копирование
```
