# AGENTS.md

## 1. Назначение

Проект превращает разрозненные входящие запросы в понятный командный центр
для координатора, который готовится к ежедневной планёрке.

Приложение должно помогать ответить:

- что горит сегодня;
- где не хватает данных;
- кто перегружен;
- какие запросы могут быть дублями;
- что относится к выбранному проекту;
- какую сводку отправить руководителю.

## 2. Карта проекта

- `README.md` — описание учебного проекта;
- `AGENTS.md` — правила для всех участников;
- `opencode.json` — разрешения OpenCode;
- `input/requests.md` — 24 исходных запроса;
- `output/task-board.md` — сводка из предыдущего урока;
- `.opencode/commands/` — готовые slash-команды;
- `.opencode/agents/` — здесь появятся проектные субагенты;
- `.opencode/skills/` — здесь появится повторяемая методика;
- `app/` — здесь должна появиться первая версия приложения.

## 3. Правила работы

- Не изменять и не удалять файлы внутри `input/`;
- сохранять исходные номера запросов от 01 до 24;
- не придумывать ответственных, сроки, проекты и источники;
- если данных нет, писать «требует уточнения»;
- возможные дубли обозначать только как предположение и объяснять причину;
- отвечать и создавать интерфейс на русском языке;
- аналитик, UX-архитектор и QA возвращают выводы, но не исправляют приложение;
- до изменения файлов сначала подготовить план;
- приложение создаёт или изменяет только Build после разрешения человека;
- готовое приложение размещать только внутри `app/`;
- не подключать внешние библиотеки, фреймворки, базы данных и API;
- первая версия должна запускаться как статический сайт.

## 4. Правила приоритета

- Высокий приоритет: есть слова «срочно», «сегодня», «завтра» либо задача
  блокирует запуск, рассылку, запись или работу другой команды;
- средний приоритет: указан срок до конца недели или конкретный ближайший день,
  но задача не блокирует запуск;
- низкий приоритет: нет срочного срока и задача не блокирует другие работы;
- если приоритет нельзя определить уверенно, требуется уточнение человека.

## 5. Критерии готовности приложения

- Существуют `app/index.html`, `app/styles.css`, `app/data.js` и `app/app.js`;
- в приложении присутствуют ровно 24 исходных запроса;
- отсутствующие сведения отмечены словами «требует уточнения»;
- показаны общее количество запросов, высокий приоритет, проблемы данных
  и возможные группы дублей;
- существует блок «Фокус дня»;
- показана нагрузка по исполнителям;
- возможные дубли сопровождаются объяснением;
- работают поиск и фильтры по источнику, проекту, приоритету и полноте данных;
- существует сброс фильтров и сообщение для пустого результата;
- существует сводка для планёрки и кнопка её копирования;
- интерфейс остаётся читаемым на узком экране;
- `input/requests.md` не изменён;
- QA вернул независимый отчёт и ничего не исправил автоматически.
