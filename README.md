# task-dispatcher

**Командный центр входящих задач** — операционный дашборд координатора,
который превращает 24 разрозненных входящих запроса в картину, готовую для
ежедневной планёрки. Приложение — статический сайт на чистом HTML/CSS/JS
без единой внешней зависимости.

За один экран координатор получает ответы на рабочие вопросы:

| Вопрос координатора | Где ответ |
|---|---|
| Что горит сегодня? | блок **«Фокус дня»** |
| Где не хватает данных? | KPI **«Требуют уточнения»** + фильтр по полноте данных |
| Кто перегружен? | блок **«Нагрузка по команде»** |
| Какие запросы — дубли? | блок **«Возможные дубли»** с объяснением |
| Что отправить руководителю? | **«Сводка для планёрки»** в один клик |

```

   24 входящих      │   app/data.js      │
   запроса ───────▶ │  requests          │

                    ┌────────────────────┐
                    │   app/app.js       │  ┌─────────────────────┐
                    │  рендеринг и       │─▶│ app/index.html      │
                    │  логика:           │  │  структурные блоки  │
                    │  KPI, фокус,       │  └─────────────────────┘

                    └────────────────────┘  │  сетка и адаптив    │

```

   │
   ▼

   │
   ▼

## Возможности

### Общий обзор (KPI)
- 4 кликабельные карточки: всего запросов, высокий приоритет, проблемы данных, группы дублей.
- Клик фильтрует таблицу или прокручивает к блоку дублей.

### «Фокус дня»
- Задачи `high`-приоритета со сроком «сегодня»/«завтра», сортировка по наступлению.
- Пустое состояние: «Нет горящих задач на сегодня и завтра».

### «Все запросы»
- Карточки дли всех 24 запросов: номер, текст, источник, проект, ответственный, срок, приоритет.
- Мгновенный поиск по тексту, ID, проекту, исполнителю и источнику.
- Фильтры: источник (5), проект (11), приоритет, полнота данных; работают по AND.
- Кнопка «Сбросить фильтры» и пустое состояние с подсказкой.

### «Нагрузка по команде»
- 11 исполнителей с полосками загрузки (зелёный ≤1 / жёлтый 2 / красный ≥3).
- Число задач, горящие задачи, проекты.
- Строка «Не назначено» для запросов без ответственного.

### «Возможные дубли»
- 4 группы предположений с объяснением «Почему похоже».
- Номера запросов кликабельны — прокручивают к карточке и подсвечивают её.

### «Сводка для планёрки»
- Готовый текст: дата, KPI, фокус дня, топ-4 нагрузки, неназначенные, дубли.
- Копирование через clipboard API с fallback на `execCommand` и обратной связью.

### Адаптивность
- ≤768px: двухколоночная сетка → одна колонка, KPI 2×2, фильтры на всю ширину.

## Данные

Файл `app/data.js` — единственный источник данных:

| Объект | Содержимое |
|---|---|
| `requests` | 24 запроса: `id`, `source`, `project`, `text`, `deadline`, `assignee`, `priority`, `dataStatus` |
| `duplicateGroups` | 4 группы дублей с `requestIds`, `description`, `reason` |
| `executors` | 11 исполнителей: `name`, `count`, `hotCount`, `projects` |
| `generateSummary()` | формирует текст сводки для планёрки |

Отсутствующие данные (`deadline: null`, `assignee: null`) отображаются как
**«требует уточнения»**. Исходные 24 запроса зафиксированы в
`references/requests.md` и не изменялись.

## Запуск

Приложение статическое. Откройте `app/index.html` в браузере или запустите
сервер:

```bash
python -m http.server 8000
# затем http://localhost:8000/app/
```

## Тесты

```bash
pip install -r requirements-dev.txt
node --check app/data.js
node --check app/app.js
pytest -v
```

Acceptance-тесты покрывают 13 критериев из `AGENTS.md` и QA-отчёта
(`tests/test_acceptance.py`, ветка `feature/acceptance-tests`).
Пример CI — `docs/ci.yml.example`.

## Ограничения

- Приложение не обращается к сети и не хранит данные пользователя.
- Показатели рассчитываются на клиенте из неизменённого набора запросов.
- Отсутствующие данные помечаются «требует уточнения».
